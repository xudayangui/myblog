Stream（流）是 Node.js 处理大数据的核心抽象。相比一次性把文件读入内存，流式处理能显著降低内存占用。这篇文章讲清楚四种流类型和实际应用。

## 为什么需要 Stream

假设要读取一个 2GB 的视频文件：

```javascript
// 传统方式：把整个文件读进内存，内存爆炸
const data = fs.readFileSync('huge-video.mp4')  // 2GB!

// 流式方式：分块处理，内存占用恒定
fs.createReadStream('huge-video.mp4')
  .pipe(fs.createWriteStream('copy.mp4'))
```

流把数据切成小块（chunk）逐个处理，内存占用和文件大小无关。

## 四种流类型

- **Readable（可读流）**：数据来源，如 `fs.createReadStream`
- **Writable（可写流）**：数据目的地，如 `fs.createWriteStream`
- **Duplex（双工流）**：既可读又可写，如 `net.Socket`
- **Transform（转换流）**：读写时可修改数据，如 `zlib.createGzip`

## 一个压缩文件的例子

```javascript
const fs = require('fs')
const zlib = require('zlib')

fs.createReadStream('input.txt')
  .pipe(zlib.createGzip())
  .pipe(fs.createWriteStream('input.txt.gz'))
  .on('finish', () => console.log('压缩完成'))
```

`.pipe()` 会自动处理背压（backpressure）——当写入速度跟不上读取速度时自动暂停读取，避免内存堆积。

## 手动处理 data 事件

```javascript
const readable = fs.createReadStream('file.txt', { encoding: 'utf8' })
let content = ''

readable.on('data', chunk => { content += chunk })
readable.on('end', () => console.log('读取完成', content.length))
readable.on('error', err => console.error(err))
```

注意：直接用 `data` 事件会切换到流动模式，此时 `pipe` 可能失效，二者不要混用。

## Transform 流：实现一行日志过滤

```javascript
const { Transform } = require('stream')

const filterError = new Transform({
  transform(chunk, encoding, callback) {
    const line = chunk.toString()
    if (line.includes('ERROR')) {
      this.push(line)
    }
    callback()
  }
})

fs.createReadStream('app.log')
  .pipe(filterError)
  .pipe(fs.createWriteStream('errors.log'))
```

## 异步迭代：更现代的写法

Node 10+ 支持用 `for await...of` 遍历流：

```javascript
async function processFile(path) {
  for await (const chunk of fs.createReadStream(path)) {
    // 逐块处理
    await handle(chunk)
  }
}
```

这种写法可以自然地用 `try/catch` 处理错误，比事件监听更清晰。

## 小结

流的价值在于**恒定内存 + 处理时间重叠**。凡是涉及大文件、网络传输、实时数据，优先考虑流。记住 `.pipe()` 帮你处理了背压，但混用 `data` 事件要小心。
