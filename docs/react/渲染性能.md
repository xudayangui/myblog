React 应用卡顿，多数时候是「不必要的渲染」导致的。这篇文章从排查工具到优化手段系统梳理。

## 先找到问题：React DevTools Profiler

打开 React DevTools 的 Profiler 面板，录制一次交互，能看到每个组件的渲染耗时和次数。颜色越黄说明越慢。重点看：

- 哪些组件渲染次数异常多
- 哪些组件渲染耗时过长
- 是否有「明明数据没变却重渲染」的组件

## 不必要的渲染从哪来

React 默认行为：**父组件渲染，子组件无条件跟着渲染**，不管 props 有没有变。

```javascript
function Parent() {
  const [count, setCount] = useState(0)
  return (
    <>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <HeavyChild />  // count 变化时它也会重新渲染
    </>
  )
}
```

## 优化手段一：React.memo

```javascript
const HeavyChild = React.memo(function HeavyChild({ name }) {
  return <div>{name}</div>
})
```

`memo` 会对 props 做浅比较，相同则跳过渲染。注意：如果 props 里有每次新建的对象或函数，浅比较永远失败，需要配合 `useMemo`/`useCallback`。

## 优化手段二：useMemo 缓存计算结果

```javascript
const sortedList = useMemo(() => {
  return bigList.slice().sort((a, b) => a.score - b.score)
}, [bigList])
```

只有 `bigList` 变化时才重新排序，避免每次渲染都做昂贵计算。

## 优化手段三：状态就近放置

最容易被忽视的优化：把状态放到真正需要它的最小组件里，而不是提升到公共父级。

```javascript
// 差：state 放在顶层，导致整个页面重渲染
// 好：把输入框和它的 state 封装成独立组件
function SearchBox() {
  const [text, setText] = useState('')
  return <input value={text} onChange={e => setText(e.target.value)} />
}
```

## 优化手段四：列表虚拟化

渲染上万条数据的列表，用 `react-window` 或 `react-virtualized` 只渲染视口内的项：

```javascript
import { FixedSizeList } from 'react-window'

<FixedSizeList height={600} itemCount={10000} itemSize={50} width="100%">
  {Row}
</FixedSizeList>
```

## 优化手段五：useTransition 处理大更新

React 18 的 `useTransition` 能把耗时更新标记为「非紧急」，保持界面响应：

```javascript
const [isPending, startTransition] = useTransition()

startTransition(() => {
  setFilteredList(expensiveFilter(input))
})
```

## 小结

优化顺序：**先用 Profiler 定位 → 状态就近放置 → memo/useMemo → 虚拟化 → useTransition**。切记不要过早优化，很多「性能问题」其实是架构问题，先让代码正确，再用数据驱动优化。
