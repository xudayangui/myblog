防抖（debounce）和节流（throttle）是前端优化高频事件的两种手段。虽然经常被一起提，但它们的语义完全不同。

## 防抖：等停下来再执行

防抖的核心：**事件触发后等待 n 毫秒，如果期间又触发了就重新计时**。典型场景是搜索框输入。

```javascript
function debounce(fn, delay = 300) {
  let timer = null
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
    }, delay)
  }
}

const search = debounce((keyword) => {
  console.log('搜索：', keyword)
}, 500)

input.addEventListener('input', e => search(e.target.value))
```

用户连续输入时不会触发搜索，停止输入 500ms 后才执行一次。

### 立即执行版本

有时希望第一次立即执行，之后停止后才重置：

```javascript
function debounceImmediate(fn, delay = 300) {
  let timer = null
  return function (...args) {
    const callNow = !timer
    clearTimeout(timer)
    timer = setTimeout(() => { timer = null }, delay)
    if (callNow) fn.apply(this, args)
  }
}
```

## 节流：固定频率执行

节流的核心：**单位时间内只执行一次**。典型场景是滚动、拖拽、按钮防重复点击。

```javascript
function throttle(fn, interval = 300) {
  let last = 0
  return function (...args) {
    const now = Date.now()
    if (now - last >= interval) {
      last = now
      fn.apply(this, args)
    }
  }
}

window.addEventListener('scroll', throttle(() => {
  console.log('滚动中...')
}, 200))
```

无论滚动多快，每 200ms 最多执行一次。

### 时间戳 + 定时器版本

上面的实现在最后一次触发时可能不执行。加上定时器保证尾部也执行：

```javascript
function throttleFull(fn, interval = 300) {
  let last = 0
  let timer = null
  return function (...args) {
    const now = Date.now()
    const remaining = interval - (now - last)
    if (remaining <= 0) {
      clearTimeout(timer)
      timer = null
      last = now
      fn.apply(this, args)
    } else if (!timer) {
      timer = setTimeout(() => {
        last = Date.now()
        timer = null
        fn.apply(this, args)
      }, remaining)
    }
  }
}
```

## 一句话区分

- **防抖**：做一件事，等你彻底停下来才做（打车拼车，等人齐了再走）
- **节流**：做一件事，固定间隔做一次（地铁发车，到点就走）

## 注意 this 和参数

两个实现里都用 `fn.apply(this, args)` 而不是 `fn(...args)`，这是为了保留原函数的 `this` 指向和参数。作为事件处理器时，`this` 应该指向触发事件的元素。
