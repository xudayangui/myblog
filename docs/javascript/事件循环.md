事件循环（`Event Loop`）是 JavaScript 异步模型的基石，也是面试高频考点。很多人的理解停留在「先同步后异步」，但一旦遇到 `Promise`、`setTimeout`、`async/await` 混排就乱了。这篇文章用一道经典题把它彻底讲清楚。

## 先看一道题

```javascript
console.log('start')

setTimeout(() => console.log('setTimeout'), 0)

Promise.resolve().then(() => console.log('promise1'))
  .then(() => console.log('promise2'))

async function asyncFn() {
  console.log('asyncFn start')
  await Promise.resolve()
  console.log('asyncFn end')
}
asyncFn()

console.log('end')
```

你能说出准确的打印顺序吗？答案是：

```
start
asyncFn start
end
promise1
asyncFn end
promise2
setTimeout
```

要理解这个顺序，需要先搞清楚微任务和宏任务。

## 宏任务与微任务

JavaScript 中有两类任务队列：

- **宏任务（Macrotask / Task）**：`setTimeout`、`setInterval`、`script` 整体代码、`I/O`、`UI 渲染`、`postMessage`
- **微任务（Microtask）**：`Promise.then/catch/finally`、`MutationObserver`、`queueMicrotask`、`async/await` 中 `await` 之后的部分

事件循环的执行顺序是：

1. 执行一个宏任务（初始时是整个 `script`）
2. 执行过程中遇到的微任务加入微任务队列
3. 当前宏任务执行完毕后，**清空所有微任务**
4. 进行渲染（如有）
5. 取下一个宏任务，回到第 1 步

关键点：**微任务优先于宏任务，且一次清空**。

## 逐步推演上面的题

1. 执行 `script`（第一个宏任务）
   - `console.log('start')` → 打印 `start`
   - `setTimeout` → 回调排入宏任务队列
   - `Promise.resolve().then(...)` → 第一个 `.then` 排入微任务队列
   - 调用 `asyncFn()`：打印 `asyncFn start`，遇到 `await`，把 `await` 之后的代码作为微任务排入队列
   - `console.log('end')` → 打印 `end`
2. script 结束，清空微任务队列：
   - 执行 `promise1` → 打印 `promise1`，其后的 `.then` 又产生一个微任务 `promise2` 排入队尾
   - 执行 `asyncFn end` → 打印 `asyncFn end`
   - 执行 `promise2` → 打印 `promise2`
3. 取下一个宏任务：`setTimeout` 回调 → 打印 `setTimeout`

于是得到最终顺序。

## async/await 的本质

`async/await` 是 `Promise` 的语法糖。`await` 会把后面的代码包装成 `.then` 回调：

```javascript
async function f() {
  const res = await something()
  console.log(res)
}

// 等价于
function f() {
  return something().then(res => {
    console.log(res)
  })
}
```

所以 `await` 后面的代码属于微任务，理解了这一点，`async/await` 的执行顺序就不难了。

## Node.js 中的差异

浏览器里事件循环相对简单，Node.js 在 11 版本之前略有不同：微任务在**每个阶段之间**执行，且 `process.nextTick` 的优先级高于 `Promise.then`。Node 11 之后已向浏览器对齐。

```javascript
process.nextTick(() => console.log('nextTick'))
Promise.resolve().then(() => console.log('promise'))
// nextTick 总是先于 promise
```

## 小结

记住三句话就够了：

1. 同步代码最先执行
2. 当前宏任务结束后，清空**所有**微任务
3. 然后才轮到下一个宏任务

把这个模型刻进脑子里，再复杂的异步题都能拆开。
